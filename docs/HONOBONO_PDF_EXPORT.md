# ほのぼの → 帳票を PDF で出力する手順

支援経過・会議録・モニタリング・アセスメント・主治医意見書は **CSV では出せない**
(ケアマネ → CSV タブは 計画書(1)/(2)/A様式 の 4 つだけ)。
これらは **印刷 → PDF** で移すしかない。

## CubePDF を使う (2026-08-31 に確立)

ほのぼの側 PC に **CubePDF** を入れて仮想プリンタにすると、保存ダイアログが出ず
**1 人 1 ファイル・自動連番・出力先固定**で出せる。押すのは「変換」ボタンだけ。

```
出力ファイル   C:\Users\KTHonsya\Box\10F内共有\ほのぼのから出力\介護支援経過.pdf
上書き設定     リネーム        → 介護支援経過(1).pdf … と自動連番
ポストプロセス  何もしない      → 変換後に PDF を開かない
```

設定は「設定を保存」で覚える。**複数人を選ぶと人数分の CubePDF ウィンドウが
まとめて開く**ので、前面から順に「変換」を押していく。ウィンドウは階段状に
ずれるので、都度その位置を見て押すこと。

⚠ **Microsoft Print to PDF は使わない。**
  - 保存ダイアログが **データがある人ごと**に出る (191 名なら 100 回超)
  - しかも開くフォルダが毎回変わるので座標を決め打ちできない
  - PDF の構造上、**1 レコードがページをまたぐと取りこぼす** (阿部代始子 43→18 件)

  3 名で試したとき「保存ダイアログは 1 回」と誤って一般化したが、
  実際にデータがあったのが 1 名だけだっただけだった。191 名で流したら延々と出た。

## 手順

### 1. 対象の利用者を見える状態にする

ほのぼの NEXT → **利用者管理 → 事業所切替**

- 1 拠点だけ → 事業所グループ (例「35 高品　居宅」) にチェック → 確定
  → その拠点の利用者だけになる (高品居宅なら 191 名)
- 全社から探す → **「(グループ選択無し)」**を選ぶと【複数事業所適用中】になり
  全事業所 7,902 名が対象になる

### 2. 帳票を開く

**ケアマネ** タブ → 出したい帳票のサブタブ

```
進捗管理 / アセスメント / 課題整理総括 / 課題分析 / 計画書 / 会議録 /
利用・提供票 / モニタリング / 支援経過記録 / 認定調査 / 主治医意見書 / 情報連携 / CSV
```

⚠ サブタブは **2 回クリック**しないと切り替わらないことがある。
   画面が変わらなければもう一度押す。

### 3. 印刷ダイアログを開く → プリンタを PDF にする

上部の **印刷** → **プリンタ設定** → 一覧の先頭 **Microsoft Print to PDF** → OK

⚠ 一覧は名前が途中で切れている。横スクロールしないと
   `Microsoft Print to PDF` か `RICOH…` か判別できない。

### 4. 利用者を選ぶ

右上の **利用者選択 → 複数** → 行をクリックして選ぶ (全選択も可)。
下に `20/ 191 人` のように選択数が出る。**この数だけ保存ダイアログが出る**と思うこと。

### 5. 期間を決める

**期間** 欄。支援経過なら移行したい範囲にする。

### 6. 印刷 → 保存

**印刷** → 部数とページ設定 → **印刷** → 保存ダイアログ

- 保存先は前回の場所を覚えている
- ファイル名は **半角英数**で入れる (CRD 越しに日本語・記号は打てない)
- 全員ぶん終わると結果一覧が出る

```
青木 春夫   印刷済み
青木 英夫   データがありません
```

### 7. こちらで受け取る

```
ほのぼの側   \\Client\C$\Users\KTHonsya\Box\10F内共有\ほのぼのから出力
こちら       C:\Users\domen-PC\Box\10F内共有\ほのぼのから出力
```

Box が同期するので数十秒で見える。

## PDF から取り込む

テキストは普通に抽出できる (画像 PDF ではない)。

```python
import pypdf
r = pypdf.PdfReader("shienkeika.pdf")
print(r.pages[0].extract_text())
```

支援経過の 1 ページ目はこう出る。

```
殿
作成年月日令和 7年12月16日
居宅サービス計画作成者氏名ほのぼの 管理者
Hana居宅高品
青木 春夫
令和 8年 8月31日居宅介護支援経過
利用者名
要介護３要介護度
内　　　　　容年月日 項　目
居宅契約・ア 二女宅を訪問し、本人と二女夫婦と面R 7/12/16
セスメント 談する。…
```

⚠ **段組がそのまま出るので行が混ざる**。年月日・項目・内容が 1 行に混在する。
  素朴な正規表現では切れないので、**Claude に読ませて JSON にする**のが確実。

```bash
node migrations/import_support_records_from_pdf.mjs --pdf <file> --office 高品
node migrations/import_support_records_from_pdf.mjs --load <抽出済み.json> --execute
```

⚠ 利用者の同定は **事業所 + 氏名**。PDF に利用者番号が無いので、
  **1 ファイルに複数拠点を混ぜてはいけない**。同姓同名は引き当てず一覧に出す。

## アセスメント固有の注意 (2026-08-31)

### 帳票は 10 種類。移すのは 生活(1)〜(5) だけ

```
生活アセスメント(1)フェースシート   生活史・相談内容・相談経路   → 移す
生活アセスメント(2)(3)              家族状況・サービス利用状況   → 移す
生活アセスメント(3)(4)              住居等の状況・制度利用       → 移す
生活アセスメント(5)                 既往歴・受診状況             → 移す
ケアアセスメント(1)〜(6)            要介護認定項目のチェック     → **見送り**
全体のまとめ                                                     → 見送り
```

ケアアセスメントは**認定調査の項目そのもの**で、当システムは認定情報を別に持っている。

### 複数人印刷で必ず SQL エラーが出る (ほのぼの側のバグ)

```
エラーコード: -195   SQLSTATE = 23000
テーブル 'com_moc_prtini_s' のカラム 'section_name' を NULL にすることはできません。
DB には変更は行われませんでした。
```

`prtini` = **印刷レイアウトの記録**。そこへの INSERT が失敗しているだけで、
**印刷そのものは成功する**。画面の赤字にも根拠がある:

> 印刷オプションを変更する場合は、利用者選択と履歴選択を単一にして変更してください

利用者ごとに 1 回出るので、**OK →「エラーの詳細を表示しますか？」→ いいえ**
を交互に押して印刷を完走させる。192 名なら 192 回。

### Enter が効かなくなることがある

支援経過では 3 秒間隔の Enter で 1:1 に追従したが、アセスメントの途中から
**キー入力が CRD 経由で届かなくなった**。そうなると 変換ボタンを 1 件ずつ
クリックするしかなく、1 件 8 秒 + 往復で現実的でない。

打ち切るときは **タスクバーの CubePDF アイコンを右クリック →
「すべてのウィンドウを閉じる」**。

⚠ 2026-08-31 はこれで **Citrix セッションごとログオフされた**。
  ほのぼのに戻るにはログオンからやり直しになる。

### フェースシートは全員ぶん出ない

192 名中 **113 名分しか存在しない**（残りは「履歴がありません」）。
アセスメント実施日はフェースシートからしか取れないので、
**フェースシートが無い人は取り込めない**（46 名）。

## 方針 (2026-08-31 user 判断)

**現役の利用者だけ出す**。全 7,900 名分は量が現実的でない。

## 週間計画・日課計画(第3表)の出し方 (2026-09-02 確立。user手動で確認)

**ケアマネ → 計画書 タブ → 週間計画 サブタブ**を開き、上部の「**計画書一括印刷**」ボタン
(「印刷」ではなくこちら)を押す。出るダイアログの「印刷帳票選択」チェックリストに
**週間計画・日課計画が既定でチェック済み**なので、そのまま「印刷」→ プリンタ設定で
CubePDF選択 → OK の通常フローで出せる(計画書(1)/(2)・利用票・利用票別表も同じ
チェックリストにあるので、必要な種類だけ絞ってもよい)。

⚠ **「プレビュー」ボタンは使わない**。プレビューでページ送りすると**CRD接続そのものが
切断される**症状が発生した(2026-09-02)。ほのぼの本体(Citrixセッション)は生きたままなので、
CRDタブを開き直せば復旧する(Citrixログオンからのやり直しにはならない)。

⚠ 事業所プルダウン(画面左上「KT居宅 高品」等)に**旧事業所名が残っていることがある**。
  対象を選ぶ前に、今使うべき事業所名で合っているか確認すること。

複数人選択時は支援経過と同じく1人1ウィンドウでCubePDFが開く(2名で確認済み)。

## モニタリング・会議録・情報連携・計画書一括(利用者単位)の出し方 (2026-09-14 確立)

### 印刷ダイアログの履歴一覧で「保存データの有無」を1クリックで判定する

⚠ **画面を開くと、保存データが無くても新規フォーマットが表示される**
(作成日=今日・作成者=ログイン中の管理者、という空の入力画面が出るだけ)。
**画面を開いただけでは保存データの有無を判定できない。**

判定するには各帳票の**印刷ダイアログで利用者をクリックする**。右側に
**履歴一覧(作成日 × 作成者)** が出るので、0件かどうかで判定できる。
2026-09-14に四街道の数名で確認した結果:

| 帳票 | 使われているか |
|---|---|
| モニタリング (計画モニタリング) | ○ (履歴あり。1名で最大3回) |
| 会議録 (サービス担当者会議の要点) | ○ (履歴あり) |
| 週間計画 | ○ (履歴あり) |
| 情報連携 (入院時情報提供書) | ○ (四街道4名中1名で履歴あり) |
| 課題整理総括 | × (4名とも0件) |
| 課題分析 | × (0件) |
| 主治医意見書 | × (6名とも0件) |
| 評価表 (モニタリング内サブタブ) | × (0件。予防様式のため要介護の利用者には無い想定) |
| 実施モニタリング | × (0件) |
| 日課計画 | × (2名とも0件) |

⚠ 少人数(1〜6名)での観測なので「0件」は「運用されていない」と断定はできない。
参考値として扱うこと。

### モニタリング記録表の出し方

**ケアマネ → モニタリング → 計画モニタリング → 印刷** → 帳票「モニタリング記録表」
選択 → 利用者選択=**単一** → 履歴選択=**複数→全選択** → プリンタ CubePDF → 横A4。
**1履歴ごとにCubePDFウィンドウが開く**(1人で複数回ぶん=複数ファイル)。

⚠ **利用者選択を複数にすると履歴選択が消え、基準日時点の最新1回だけ**しか出ない。
過去の回もまとめて出すには**単一×履歴複数を1人ずつ繰り返す**しかない
(2026-09-14時点で見えている範囲)。

⚠ 帳票の選択肢は他に モニタリング記録表一覧 / モニタリング記録表(カスタマイズ様式) がある。
サブタブに 評価表 / 実施モニタリング もある。

### 会議録 (サービス担当者会議の要点・第4表) の出し方

ケアマネ → 会議録 → 印刷。テキスト抽出は可。**検討内容欄が「別紙参照」になっており、
本文は2ページ目の「結論　別紙1」以降に流れる**(1ページ目だけでは本文が取れない)。

### 情報連携 (入院時情報提供書・退院退所情報記録書) の出し方

情報連携 → 印刷。テキスト抽出は可だが**大半がチェックボックス(□/✓)の様式**。
アセスメントPDFの ü 記号検出と同じ手法(座標でチェック記号の近傍テキストを拾う)が要る。

### 計画書一括印刷は「利用者単位」で出すと第7表(別表)の氏名紐付け問題が解決する

木更津で「別表のページに氏名が無く、ページ順でしか第6表と対応付けられない」
問題があった(このファイル冒頭の「別表を出すときの必須条件」参照)。

**計画書一括印刷で両面印刷オプションを「利用者単位」にし、印刷設定でサービス提供年月と
利用者(複数選択可)を指定**すると、**1利用者=1PDFファイル**にまとまり、その中で
利用票→別表が連続して出る。**別表自体には氏名が無いままだが、同じファイル内の
利用票の人=別表の人、と確定できる**ため、ページ順推定に頼らずに済む。

⚠ 週間計画のヘッダ「令和　年　月分」が**空欄になる人がいる**(作成年月日自体は入っている)。

### 旧字体・異体字の注意

**画面上の表記とPDF上の表記が異なることがある**(例: 画面「浅井 珠恵」→ PDF「淺井 珠惠」)。
★同一PDF内でも表記が揺れることがある(「淺井 珠惠」と「淺井　珠恵」が同じ書類内に混在)。
NFKCでは畳まれない異体字(淺→浅・惠→恵 等)なので、取込scriptの利用者名突合では
★異体字の畳み込みが必須。未対応だと未登録として引き当てに失敗する。

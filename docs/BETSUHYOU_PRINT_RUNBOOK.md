## 11. ★ 「予定」ラベルの x を 取込の前に必ず数える (2026-11-14 実測)

利用票 PDF は **印刷設定が違うと読み取りが壊れる**。判定は「予定」ラベルの x 座標で付く。

```
x=326   ★ いつもの出し方。★ 長いサービス名が 1 行に収まる
x=342   ★ 違う設定。★ 長い名前が 2 行に折り返し、★ 後半だけが読まれる
```

実測 (高品 2026-06):

```
居宅/高品利用票全CM.pdf                       161 頁  すべて x=326   ★ 正しい
_cm別/高品利用票{佐藤,小林,白倉,細岸,藤本}CM.pdf  158 頁  すべて x=342   ★ 壊れる
2026-07 高品 (15 拠点と同じ設定で刷った)         161 頁  すべて x=326   ★ 正しい

★ _cm別 にしか無いサービス名  65 種類 / 615 行
   例) 名前が空 151 行 / 「推進体制加算」46 / 「算Ⅰ」32 / 「練加算Ⅱ」27 / 「供体制加算Ⅰ」25
   ★ 同じ行を 全CM では「通所介護科学的介護推進体制加算」35 /
     「通所介護個別機能訓練加算Ⅱ」27 と最後まで読めている
```

`migrations/import_riyouhyou_bundle.mjs` の pageAudit が
**「印刷設定の違うファイル n 本」**と警告する。**取込の冒頭で 0 本を確かめること。**

### ⚠ ただし「x=342 の束がある」と「取込が壊れている」は別の話

★ 2026-11-14 に、この 2 つを結び付けて **誤った結論を出しかけた**。

```
状況証拠   ① 高品 2026-06 に x=342 の束がある
          ② 「単位も種類も無い行 42 行」が 高品だけに偏っている（他拠点は 0〜8 行）
誤った結論  ★ 「折り返しが原因。全CM から取り込み直せば直る」
実データ    ★ 取込元は 139 件すべて 全CM。★ CM別 からの取込は 0 件
          ★ 42 行の内訳は 「(その他)」41 行（保険外。マスタに無く単位が空で正しい）
                       ＋ 印字が途中で切れた名前 1 行
→ ★ 直す必要が無かった
```

🔴 ★ **取り込み直していたら事故だった。**`--only-new` を外すと `services` を丸ごと
作り直すので、★ 後から backfill で入れた単位数が 1,330 行ぶん静かに消えていた。

→ ★ **取り込み直す前に、直す対象が本当に壊れているかを実データで 1 件見ること。**

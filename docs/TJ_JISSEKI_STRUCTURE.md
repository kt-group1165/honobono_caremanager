## ⚠ 算定時間は 10 進時間 ×100

`0750` は **7.50 時間**であって 07:50 (7時間50分) ではない。

実証 (やわた 宮原和世 2026-06):

```
1300-1830 (5.5h) + 1630-1830 (2.0h) → 0750 = 7.5h
1100-1830 (7.5h) + 1630-1830 (2.0h) → 0950 = 9.5h
```

2.00h / 5.00h のように 30 分刻みでない値だと HHMM と区別が付かないので、
**必ず .5 が出る例で確かめること**。

## わかったこと: ほのぼのは 1 日の重訪を合算する

算定時間はその日の **最後の行**に、その日の重訪の**合計**として入る。
つまり「同じ日に複数回入った重訪」は 1 本の積み上げとして算定される。

合算した総時間を時間帯で按分し、それぞれの区分で段を積む。

```
早朝  6:00-8:00     122xxx
日中  8:00-18:00    121xxx
夜間 18:00-22:00    123xxx
深夜 22:00-6:00     124xxx
```

## 当方との差 (2026-08-30 時点・未修正)

```
(a) 時間帯を分割していない
    宮原和世 6/6 13:00-18:30 → 当方は全部「重訪Ⅱ日中」。18:00 以降も日中扱い。
    身体介護は「身体日２．５・夜０．５」と正しく分割できているので、重訪だけの問題。

(b) 2人派遣の判定が違う
    当方は「同一利用者×日で時刻が重なる = 同時2人派遣」と **推測**している。
    ほのぼのは人数をデータで持っていて、重なっていても 1 人扱いのことがある
    (宮原は TJ 人数=1 なのに当方は 121272/121282 の・2人コードを出している)。
```

⚠ ほのぼのも ・2人 コード (121272 / 121282 / 121442 等) は使っている (各 1〜3 件)。
**使い分けの条件がデータのどこにあるかを特定してから直す**。
推測で直すと誤請求になる。

増分の回数は理屈どおり:

```

夜間  8日× 1.0/0.5=2                                =         16 ✓

```

```
増分 [7.5, 8.0)  → 「８．５」    長い日 1 回              → 4       =  4 ✓
増分 [8.0, 8.5)  → 「１２．０」  長い日 1 回              → 4       =  4 ✓
```

## ★ 算定ルール確定 (2026-08-30)

マスタの重訪コードは **各時間帯 16 段**。早朝/日中/夜間/深夜で同じ段があり単位数だけ違う。

```
1.0 1.5 2.0 2.5 3.0 3.5 4.0                          基本段 (4時間まで30分刻み)
8.0 8.5 12.0 12.5 16.0 16.5 20.0 20.5 24.0            増分
```

| 段 | 早朝 | 日中 | 夜間 | 深夜 |
|---|---|---|---|---|
| 8.0 | 122221 (115) | 121221 (92) | 123221 (115) | 124221 (138) |
| 8.5 | 129081 (121) | 129025 (97) | 129137 (121) | 129193 (146) |
| 12.0 | 122231 (115) | 121231 (92) | 123231 (115) | 124231 (138) |

### ルール

```
1. その日の重訪を **訪問順に並べて時間を累計**する
   ⚠ 時刻が重なっても合算する。**2人派遣にしない**
2. 累計 0〜4.0h は基本段 (1.0/1.5/…/4.0)。その時間が属する時間帯のコード
3. 4.0h 超は 30 分ごとの増分。各増分は
   ・その 30 分が属する時間帯 (早朝 6-8 / 日中 8-18 / 夜間 18-22 / 深夜 22-6)
   ・段 = **「累計終了時刻 以上 で最小の段」**
```

⚠ **「以上」がポイント**。終了 8.0 を「8.0 を超えたから 8.5」と読むと日中が 44 になって
  合わない。**8.0 ちょうどは 8.0 段**。

### 検算 (宮原和世 長い日 9.5h)

```
ヘルパーA 11:00-18:30   日中 累計 0→7.0    夜間 7.0→7.5
ヘルパーB 16:30-18:30   日中 累計 7.5→9.0  夜間 9.0→9.5

日中の増分  終了 4.5〜7.0 → 8.0  × 6
           終了 8.0      → 8.0        (8.0 以上で最小の段 = 8.0)
           終了 8.5      → 8.5
           終了 9.0      → 12.0
夜間の増分  終了 7.5 → 8.0 / 終了 9.5 → 12.0
```

短い日 (7.5h) と合わせた 8 日分の合計が伝送と**5 コードとも完全一致**する。

```
121221 日中 8.0   48 ✓      123221 夜間 8.0   12 ✓
129025 日中 8.5    4 ✓      123231 夜間 12.0   4 ✓
121231 日中 12.0   4 ✓
```

## ★ 決着: 稼働データ (MEISAI) と実績記録は **別物**

2026-08-30 にほのぼのの画面で確認した。
サービス費等請求システム →【実績記録】→ 対象者 →【編集】

```
日1  0900-1200
日1  1300-1700   算定時間数 0700    ← 12:00-13:00 の行が **そもそも無い**
日10 0900-1230
日10 1330-0000   算定時間数 1400    ← 12:30-13:30 が無い
```

**12:00-13:00 (昼の休憩) は実績記録票に入力されていない。**
MEISAI (稼働データ) は **給与計算用**なので休憩も含めて 3 行あるが、
**請求用の実績記録は休憩を除いた 2 行**しか入っていない。

```
MEISAI (賃金集計)     09:00-12:00 + 12:00-13:00 + 13:00-17:00   8.0h  給与の対象
実績記録 (請求)       09:00-12:00 +               13:00-17:00   7.0h  請求の対象
```

⚠ **MEISAI を実績としてそのまま取り込むと、休憩ぶんまで請求してしまう** (過大請求)。
  稲葉裕子 1 人で 30 日中 22 日、1 時間ずつ多い。

### 制度上の建て付け (2026-08-30 user 確認)

```
09:00-12:00  サービス提供   給与 ○   請求 ○
12:00-13:00  休憩          給与 ○   請求 ✕   ← 事業所の持ち出し
13:00-17:00  サービス提供   給与 ○   請求 ○
```

請求できるのは **サービスを提供した時間だけ**。休憩中は支援していないので報酬は出ない。
一方、給与は労働時間に対して払うので **休憩は有給**。
NEXT の賃金集計に 12:00-13:00 の「算定時間 001:00」が入っているのがその証拠。

⚠ **同じ訪問なのに給与と請求で時間が違う**のが正しい。この 1 時間は事業所の持ち出し。

⚠ ほのぼのは 給与用 (NEXT 賃金集計) と 請求用 (more 実績記録票) を
  **別々の画面に二重入力**している。片方だけ直すと整合が崩れる構造。
  新システムは **シフト 1 行に「休憩」区分を持たせて 1 入力から出し分ける**。

### ⚠ billable フラグでは重訪の休憩は落とせない (2026-08-30 に判明)

`kaigo_visit_schedule.billable` を足したが、**重訪には効かない**。
格納の仕方がサービスによって違うため。

```
居宅介護・同行援護   1 訪問 = 1 行 (時刻と内容が一致)      → billable で落とせる
重度訪問介護         1 日 = **代表行に段を全部載せる**      → billable では落とせない
```

実例 (稲葉裕子 6/1)。当方は 15 行すべてが `09:00-12:00`:

```
09:00-12:00  重訪Ⅱ日中１．０
09:00-12:00  重訪Ⅱ日中１．５
…
09:00-12:00  重訪Ⅱ日中８．０   × 8
```

**休憩の行が存在しない。** 休憩は「余分な 1 行」ではなく **段の数**に化けている
(8.0h ぶんの段が積まれている。正しくは 7.0h ぶん)。
行を落とす方式では段を減らせないので、**取込時に段を計算する元の時間を減らす**しかない。

⚠ billable の設計自体は正しい (居宅介護・同行援護には効く)。重訪だけ別対応が要る。

### どう直すか

MEISAI には休憩を示す列が無い (3 行とも「重度15％」で、違うのは時間の長さだけ)。
判定するなら次のいずれか。

```
① ほのぼの側の **実績記録票** を別途もらう (TJ 伝送がそれ。既に手元にある)
   → 過去分は TJ から起こすのが確実
② 同一利用者・同一職員・連続する行のうち、昼をまたぐ 1 時間を休憩とみなす
   → 規則が本当にこれで良いかは要確認。他拠点でも成り立つか未検証
③ 運用開始後は **シフト側で休憩を持つ** (kaigo_visit_schedule に休憩の概念を足す)
```

⚠ 過去分は ① が確実。TJ の算定時間 (c[17]) がその日の請求対象時間そのもの。

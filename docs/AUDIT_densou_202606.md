### ✅ G+I. 公費請求額が 0 の併用ケースで公費欄が丸ごと落ちていた — **是正済み**

同じ根っこ。`build.ts`:

```ts
const hasKohi = r.kohiTandoku || !!(r.kohiHobetsu && (r.kohiAmount ?? 0) > 0);
```

**公費請求額が 0 だと `hasKohi` が false** になり、公費負担者番号 (項7)・受給者番号 (項8)・
公費対象単位数・公費請求額・公費本人負担 が**すべて空**で出る。

例 姉ム `1000149649` 鈴木 渉 (生保併用・本人支払額 1,192円):

| | 項17 利用者負担 | 項18 公費対象単位 | 項19 公費請求 | 項20 公費本人負担 |
|---|---|---|---|---|
| 新 | 1,192 | (空) | (空) | (空) |
| ほ | 0 | 1,114 | 0 | 1,192 |

生保が 0 円負担で本人が全額払うケースでも、**公費欄は出さなければならない**。
当システムは本人負担を「保険の利用者負担」欄に入れてしまっている。

`0000350884` 齊藤 一夫 (茂原) は公費欄は出ているが項17 にも 4,000 を重複して入れている。

**対応 (適用済み)**:

1. `hasKohi` を `kohiTandoku || !!kohiHobetsu` に変更 (公費請求額 0 でも公費欄を出す)
2. 明細書 項35 / 集計 項17「利用者負担額」から**公費分の本人負担を除く**
   (`userAmount − kohiHonninFutan − kohi2HonninFutan`)。生保の全量公費では
   aggregate が `userAmount = kohiHonninFutan` としているため、引かないと同じ額を
   項35/17 と項41/20 に二重計上する。本人負担上限 0 円の従来ケースは差引 0 = 挙動不変

**⚠ ここで一度やりすぎた**: 請求書 (7111/7113) の利用者負担合計まで「保険分のみ」にしたら
茂原が **-4,000円ズレた**。ほのぼの実伝送では **請求書の利用者負担合計は公費分の本人負担も
含む総額**で、明細書の項35/17 が「保険分のみ」なのとは別物だった。請求書側は元に戻した。

結果: 茂原 338→**340**一致 (明細 112→113一致)、姉ム 303→**306**一致 (明細 99→100一致)。
大網・総合事業は該当ケースが無く変化なし・退行なし。
